## 2. 存储：占用、写回与尝试记录

- [x] 2.1 实现 `claim_due(conn, now, limit, lease_ms)`：用单条 `UPDATE … RETURNING` 取出两类通知——已到期的 pending 通知，以及占用已过期的 delivering 通知。同时写入新的 `lease_token`、`lease_until`，并给 `attempt_count` 加 1。
  测试要覆盖：未到期的通知不被取出；终态的通知不被取出；占用过期后可以被重新取出；同一时刻对同一条通知只能有一个有效占用。[需求"带期限的占用"、"投递状态模型"]
- [x] 2.2 实现写回函数：标记已送达、标记失败（带原因）、安排重试（写入 `next_attempt_at`）。这三个函数都带 `lease_token` 做 fencing，并在同一个事务里插入一条尝试记录。
  测试要覆盖：持有过期占用的旧持有者写回时不生效，返回"占用已丢失"；尝试记录按顺序写入。[场景"过期占用的结果被丢弃"、需求"记录每次投递尝试"]

## 3. 投递策略（纯函数）

- [x] 3.1 实现 `classify(status_code | error)`，按照 2xx、3xx、4xx（单独处理 408 和 429）、5xx 以及各类传输错误进行分类。用参数化测试覆盖每一类的边界值，包括 200、299、301、302、400、404、408、429、500、503。[需求"失败分类"]
- [x] 3.2 实现 `next_attempt(n_failures, now, retry_after, created_at, expires_at, cfg, rng)`，返回"在某个时间重试"或"终态（重试耗尽或已过期）"。
  - 退避间隔为 `min(base·2^(n-1), cap)`，再叠加 ±20% 抖动。
  - Retry-After 支持秒数和 HTTP-date 两种格式，取值限制在 [1s, 1h]。
  - 有效截止时间取 `min(受理时间 + 最大重试时长, expires_at)`。如果 `candidate = now + delay` 不早于有效截止时间，就令 `next = 有效截止时间`，不做提前或压缩。另提供 `deadline_reason(...)`，按哪个期限先到返回重试耗尽或已过期，两者相同时返回已过期。

  测试时固定随机数种子，覆盖以下场景：间隔逐次增长并达到上限；遵守 Retry-After（120s）；Retry-After 超出上限时被截断；候选人给的例子（10:00 失败，算出 10:10，过期时间 10:05，结果 `next` 为 10:05 且状态未被标记为过期）；重试期限先到时原因为重试耗尽；两者同时到时原因为已过期。[需求"退避重试且计划持久化"、"重试期限与过期进入终态"]

## 5. 单次投递

- [x] 5.1 实现 `deliver_one(claimed, client, guard, clock, cfg)`，按以下顺序执行：
  1. 发送前检查：如果 `now` 已不早于有效截止时间，就不发送，直接按先到的期限记录失败原因。
  2. 严格模式的地址校验。
  3. 用 httpx 发送请求：设置 `follow_redirects=False`；在提交的 Header 上加入 `X-Notification-Id` 和 `X-Notification-Attempt`，同名时覆盖；以流式方式最多读取 1KB 响应。
  4. 对结果分类，调用写回函数。

  用假下游测试以下场景：
  - 200 → 已送达，并且 method、url、body、headers 原样到达。
  - 400 → 永久失败，只收到 1 次请求。
  - 302 → 不跟随，永久失败。
  - 429 和 500 → 进入重试。
  - 连接被拒绝 → 进入重试。
  - 投递时解析到内网 → 目标被禁止，并且不发送。
  - 投递时解析失败 → 进入重试。
  - 已过期 → 不发送，失败原因为已过期。
  - 已超过重试期限 → 不发送，失败原因为重试耗尽。

  [需求"仅在收到 2xx 后标记已送达"、"失败分类"、"透传稳定的通知 ID"、"投递前校验目标地址"、"重试期限与过期进入终态"]
- [x] 5.2 测试"下游已处理但响应超时"：假下游先记录请求，再延迟超过请求超时才返回。断言通知进入重试；第二次投递成功后，下游收到 2 次带相同 `X-Notification-Id` 的请求，`X-Notification-Attempt` 分别为 1 和 2。[场景"下游已处理但响应超时"、"重试时 ID 不变"]

## 6. worker 循环与入口

- [x] 6.1 实现 `Worker`：
  - 主循环按线程池空闲名额调用 `claim_due`，把占到的通知交给 `ThreadPoolExecutor`；没有到期的通知时，休眠 poll 间隔。
  - 收到 `stop()`，或者 SIGTERM、SIGINT 时，停止占用新的通知，等正在投递的完成后再退出。

  用假时钟和假下游测试：
  - 先 500 后 200 时，最终为已送达，并有 2 条尝试记录。
  - 持续返回 500 时，相邻两次尝试的间隔逐次增长。
  - 下游持续返回 500 直到超过截止时间，最终为重试耗尽，并且截止时间之后下游不再收到请求。
  - 候选人给的例子端到端走一遍（10:00 失败、算出 10:10、过期时间 10:05）：10:05 之前不再发请求；推进到 10:05 之后的一个 poll 周期，状态变为已过期；下游一共只收到 1 次请求。
  - 停止时会等正在投递的通知完成。

  [场景"先失败后成功"、"间隔逐次增长"、"重试耗尽"、"尝试记录"]
- [x] 6.2 测试"重启后不提前重试"：

  2. 停止 A，在同一个数据库上新建 worker B。
  3. 在原定的重试时间之前推进假时钟，断言不会发生投递。HTTP 超时 10 秒
  4. 推进到重试时间之后，断言恰好发生 1 次投递。

  [场景"重启后不提前重试"]
