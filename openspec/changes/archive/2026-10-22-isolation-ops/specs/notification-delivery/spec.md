# Spec Delta

## ADDED Requirements

### Requirement: 按目标限制并发投递
系统 MUST 限制同一目标 host 同时处于"投递中"的通知数量，默认最多 4 条，可配置。达到上限时，该 host 的其他到期通知 MUST 继续等待，其他 host 的到期通知 MUST 照常被取出。这一限制 MUST 在投递进程重启后依然生效。

#### Scenario: 慢下游不拖累其他下游
- **WHEN** 下游 X 的每个请求都要超时才结束，X 有大量到期通知，下游 Y 同时也有到期通知
- **THEN** 同时投递给 X 的请求不超过上限，Y 的通知仍能及时被投递，延迟不受 X 影响

#### Scenario: 同一 host 不超过上限
- **WHEN** 同一 host 有 10 条到期通知，上限为 4
- **THEN** 任一时刻，该 host 处于"投递中"的通知不超过 4 条

#### Scenario: 占用过期的通知不占名额
- **WHEN** 某 host 处于"投递中"的通知，其占用已经过期
- **THEN** 这些通知不计入该 host 的并发数，可以被重新取出

## MODIFIED Requirements

### Requirement: 重试期限与过期进入终态
每条通知的截止时间，取"重试窗口起点 + 最大重试时长（默认 24 小时，可配）"与 `expires_at` 中较早的那个。重试窗口起点是受理时间，或者最近一次人工重放的时间。每次发送前，系统 MUST 检查截止时间；已到截止时间时，MUST NOT 发送，并把通知置为失败终态：重试期限先到，原因为重试耗尽；`expires_at` 先到，原因为已过期。按正常规则算出的下一次重试时间如果不早于截止时间，系统 MUST 改为在截止时间把通知置为失败终态，不再发请求。

#### Scenario: 重试耗尽
- **WHEN** 目标持续返回 500，直到超过最大重试时长
- **THEN** 该通知进入失败终态，原因为重试耗尽，之后不再投递

#### Scenario: 已过期不再发送
- **WHEN** 一条通知在等待重试期间超过了它的 `expires_at`
- **THEN** 系统不再向目标发送它，该通知进入失败终态，原因为已过期

#### Scenario: 下一次重试晚于过期时间
- **WHEN** 10:00 投递失败，按正常规则下一次重试应在 10:10，而该通知的 `expires_at` 为 10:05
- **THEN** 10:00 时该通知仍处于"待投递"，不会被提前标记为已过期；此后不会再发出请求；在 10:05 之后的一个轮询周期内，它进入失败终态，原因为已过期

#### Scenario: 截止时间前不提前重试
- **WHEN** 按正常规则算出的下一次重试时间晚于截止时间
- **THEN** 系统不会为了在截止时间前再试一次而把重试时间提前

#### Scenario: 重放后重新计算重试期限
- **WHEN** 一条通知受理 25 小时后因重试耗尽而失败，随后被人工重放
- **THEN** 它的重试期限从重放时刻重新计算，能够被再次投递，不会因为受理时间早于 24 小时之前而立即失败
