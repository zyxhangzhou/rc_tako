# Spec Delta

## Purpose

让提交方在下游恢复或配置修正后，对已进入失败终态的通知发起人工重放，补救自动重试无法挽回的投递，同时不绕过业务给出的过期约束。

## ADDED Requirements

### Requirement: 重放失败的通知
系统 MUST 允许提交方对处于失败终态、且失败原因不是"已过期"的通知发起重放。重放成功时，系统 MUST 返回 202，把通知置为"待投递"并立即可以被取出，同时 MUST 从重放时刻重新计算重试期限。重放后的投递 MUST 沿用原来的通知 ID，尝试序号接着之前的继续递增。

#### Scenario: 重放永久失败的通知
- **WHEN** 一条通知因目标返回 400 而失败，下游修正之后，提交方发起重放
- **THEN** 返回 202，该通知被再次投递并最终"已送达"，下游收到的 `X-Notification-Id` 与之前相同

#### Scenario: 重放重试耗尽的通知
- **WHEN** 一条通知因重试耗尽而失败，提交方发起重放
- **THEN** 返回 202，该通知重新获得完整的重试期限

#### Scenario: 尝试序号连续
- **WHEN** 一条在第 2 次尝试后失败的通知被重放，并且投递成功
- **THEN** 重放后那次请求的 `X-Notification-Attempt` 为 3

### Requirement: 不可重放的情况
以下情况下，系统 MUST 拒绝重放并返回 409，通知保持不变：
- 失败原因为"已过期"。
- 当前时间已经超过该通知的 `expires_at`。
- 通知已送达。
- 通知尚未进入终态。

并发的多个重放请求 MUST 至多只有一个成功。

#### Scenario: 已过期的通知不可重放
- **WHEN** 提交方对一条失败原因为"已过期"的通知发起重放
- **THEN** 返回 409，通知状态不变

#### Scenario: 已超过 expires_at 的通知不可重放
- **WHEN** 一条通知因目标返回 400 而失败，此后已经超过它的 `expires_at`，提交方发起重放
- **THEN** 返回 409

#### Scenario: 已送达的通知不可重放
- **WHEN** 提交方对一条已送达的通知发起重放
- **THEN** 返回 409

#### Scenario: 未进入终态的通知不可重放
- **WHEN** 提交方对一条正在等待重试的通知发起重放
- **THEN** 返回 409

#### Scenario: 并发重放
- **WHEN** 提交方对同一条失败的通知同时发起多次重放
- **THEN** 只有一次返回 202，其余都返回 409

### Requirement: 重放的访问控制
系统 MUST 要求重放请求携带有效的调用方 token，缺失或无效时返回 401。通知不存在，或者属于其他调用方时，系统 MUST 一律返回 404。

#### Scenario: 重放他人的通知
- **WHEN** 调用方 B 对调用方 A 的失败通知发起重放
- **THEN** 返回 404，通知状态不变
